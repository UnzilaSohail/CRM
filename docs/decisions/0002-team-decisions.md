# 0002 Decisions taken by the team (boss delegated)

Date: 2026-10-24. Status: **accepted**. Supersedes the "provisional" status of 0001.

The stakeholder was asked about the open decisions (requirements doc section 12) and answered "decide it yourselves". The team (Aiza, Unzila) therefore decides, writes the decision down, and builds on it. Anything below can be changed later by editing this file and the matching config; nothing here is hard-wired except where noted.

| Area                        | Decision                                                                                                                                                                                                                                                                        | Where it lives                              |
| --------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------- |
| MVP scope                   | Billing, invoices, opportunity pipeline and profitability are **Phase 2**. MVP is customers, projects, tasks, attendance and time, KPIs, deviation alerts, client portal.                                                                                                       | Roadmap in `plan.md`                        |
| Product name                | Working name **AiNetworks CRM**. White-label branding is a per-tenant setting added later.                                                                                                                                                                                      | -                                           |
| Mobile                      | Responsive **PWA** at launch. Native apps only if the pilot shows a need.                                                                                                                                                                                                       | `apps/web` (manifest, service worker)       |
| Hosting                     | Containerised and cloud-neutral. Pilot on a cheap managed stack, AWS through Terraform when the client count justifies it.                                                                                                                                                      | `docker-compose.yml`, `infra/`              |
| Notifications               | **Email and in-app** first. SMS and WhatsApp are Phase 2.                                                                                                                                                                                                                       | `apps/worker` notifications job             |
| KPI formulas                | The formulas in `docs/requirements/kpi-dictionary.md` are **approved as written**. Project progress uses the milestone weights the project manager sets. Customer-level rollups use a simple average of that customer's projects and the screen says so.                        | `packages/kpi-engine`                       |
| Employee progress           | Counts only once a **lead or manager approves** it. Employees may start and pause tasks but cannot mark them done.                                                                                                                                                              | `TasksController`, `EMPLOYEE_TASK_STATUSES` |
| Alert levels                | Under 25% dashboard only, 25-49% watch (employee), 50% and above critical (employee and manager, explanation required). Thresholds editable per tenant.                                                                                                                         | `computeDeviation`, Settings                |
| Alert escalation            | A critical alert that nobody acknowledges is reminded every 24 hours and escalated to the CEO after 48 hours.                                                                                                                                                                   | Worker reminders job (to build)             |
| Attendance                  | One check-in and one check-out per person per day, counted in the tenant time zone. Working week Monday to Friday; public holidays are a per-tenant calendar. Leave is requested by the employee and approved by a lead or manager. Corrections are made by a manager, audited. | `AttendanceController`, Settings            |
| Geolocation                 | **Off.** No location is collected until a written policy and employee consent exist. The columns stay empty.                                                                                                                                                                    | `Attendance.lat/lng` unused                 |
| Data retention              | Audit events are never deleted. Operational data (tasks, time, chat, documents) is kept while the customer is active and for 24 months after the account is archived, then deleted on request or schedule. Backups are kept 30 days.                                            | Policy; deletion job to build               |
| Client publication workflow | Nothing is visible to customers by default (`clientVisible = false`). Only a project manager or the CEO can publish or unpublish a milestone, task or document, every change is audited, and the portal returns only an allow-listed set of fields.                             | `PortalController`, `clientVisible` columns |
| Roles and access            | The matrix in `docs/requirements/permissions-matrix.md` is approved, including the provisional task rules.                                                                                                                                                                      | `packages/types`                            |

## How decisions change from here

1. Edit this file (or add `0003-...`) and say why.
2. Update the config or code it points to, with a test.
3. Note it on the Jira task. No need to wait for the stakeholder; tell them in the weekly update.
